# Playground convergence — phase 1

The Swift ExpenseGuard experiment already has a native closed-outcome core,
effect shell, recorded compiler/test evidence and retained mutation limits.
SwiftAssay remains a lexical observation tool; its clean output is not semantic
or runtime assurance.

The next safe increment is an immutable configuration boundary in the Swift
specimen: supplied key/value text becomes validated settings or named issues.
Keep compiler mode 6 and the existing fresh-output runner. Do not make a Swift
`Codable` or date API sample merely to match C#, turn policy into an app DSL, or
promote lexical findings into application verification.
